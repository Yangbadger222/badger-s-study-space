<div align="center">

**把问题、资料、实验和长期记忆，组织成一个真正能持续使用的学习工作台。**

## 这个空间解决什么问题

普通聊天工具擅长回答一次性问题，却很难把一次阅读变成下一次可以复用的上下文。这个项目把学习过程拆成可持续维护的几层：

- **对话层**：围绕一个问题持续追问、澄清、推导和复盘；
- **知识层**：把 PDF、网页、Markdown、代码和笔记整理成可检索的知识库；
- **工作层**：在研究、解题、写作、可视化和练习之间共享上下文；
- **记忆层**：保留重要事实、学习进度、偏好和下一步计划；
- **伙伴层**：为不同主题配置独立的角色、工具、资料和长期记忆。

这里的目标不是“生成更多文字”，而是让每个结论都能回到来源，让每次实验都留下可以复现的路径。

## 核心能力

| 能力 | 作用 |
| --- | --- |
| 对话与推理 | 统一的多轮上下文、工具调用和流式输出 |
| 深度研究 | 拆解问题、检索资料、整理证据并生成报告 |
| 知识库 | 文档解析、切分、向量检索和多种检索后端 |
| 课程与练习 | 章节化学习、测验、掌握度路径和题库 |
| 写作工作台 | 多文档协作、结构化草稿、导出和版本留痕 |
| 可视化 | SVG、Chart.js、Mermaid、HTML 和动画输出 |
| 学习伙伴 | 独立人格、知识库、技能、工具与消息渠道 |
| CLI / Web / API | 浏览器、命令行和 WebSocket API 共用同一套运行时 |

## 快速开始

### 1. 准备环境

- Python 3.11–3.13
- Node.js 20+
- 一个可用的模型服务配置

```bash
python -m venv .venv
source .venv/bin/activate       # Windows: .venv\Scripts\activate
pip install -e ".[all]"
```

### 2. 准备前端

```bash
cd web
npm ci
npm run build
cd ..
```

### 3. 启动本地工作台

推荐通过仓库中已有的启动脚本运行后端与前端。首次启动后，在设置页面填写模型服务、嵌入模型和检索参数；本地数据会写入 `data/`，不会进入版本控制。

## 学习资料工作流

```text
收集资料 → 标注来源 → 建立知识库 → 提出问题
                              ↓
                  研究 / 解题 / 写作 / 可视化
                              ↓
                 记录结论、证据、实验与下一步
```

建议每篇教程或论文都记录：

- 来源、版本和阅读状态；
- 问题定义、方法、数据和评测；
- 可执行的环境、命令和验证标准；
- 已确认事实、个人推断和待验证假设；
- 对当前项目的启发、限制与下一步。

## 配置与数据

- `.env.example`：环境变量模板；
- `data/user/settings/`：本地模型与服务配置；
- `data/knowledge_bases/`：知识库原始文件和索引；
- `data/partners/`：学习伙伴配置与工作区；
- `data/user/workspace/`：笔记、书籍、记忆和生成文件。

运行数据可能包含个人资料、密钥或索引缓存，默认不会提交。分享项目时，请先确认没有把 `.env`、私密文件和本地数据库加入提交。

## 设计原则

1. 证据优先：结论尽量能回到原始资料。
2. 上下文可见：让工具、记忆、来源和推理过程可检查。
3. 组件可替换：模型、嵌入、检索、解析和消息渠道都保持可插拔。
4. 本地优先：个人资料和运行状态默认留在自己的工作区。
5. 记录下一步：每次阅读和实验都留下可执行的后续动作。
